## 1. Architecture overview and design principles

Five layers, each with one job. This is what the WBS calls "architecture (10)" and it is scored on whether these boundaries actually hold, not on whether the words appear in the README.

| Layer | Job | Must never do |
|---|---|---|
| **Adapters** (`adapters/`) | Talk to the outside world (Graph, Power Automate) behind a narrow interface. Mock and real implementation are interchangeable via config. | Contain business logic. No Graph type may leak past this layer (CHN-03). |
| **Detection** (`detection/`) | Decide what counts as an update — rules first, model for the remainder. | Let the model see a message a rule already settled (CHN-08/09). |
| **Participation** (`participation/`) | Pure set arithmetic: roster − contributors, three honest states. | Ever call the LLM. This is arithmetic, not judgement (CHN-10). |
| **Grounding** (`grounding/`) | Verify every generated fact carries a real message ID and every quote is a literal substring. | Let an ungrounded line reach a summary (SPN-06). |
| **Approval / Service** (`approval/`) | Gate every outbound action (publish, nudge, escalate) behind an approval status, enforced at the service layer regardless of caller. | Be bypassable via direct adapter call (SPN-08/09). |

**Why this shape, in SOLID terms** (relevant to your coding-standards preference):
- **Single Responsibility** — facts are computed in Python (rules, ledger, arithmetic); prose is generated by the LLM. Never mixed in one function (CHN-13's "facts in code, prose from the model" split).
- **Open/Closed** — the LLM gateway (SPN-02) is one call site; swapping Claude API for a local Ollama model is a config change, not a code change.
- **Liskov substitution** — `MockTeamsReader` and `GraphTeamsReader` implement the identical `TeamsReader` interface; any code depending on the interface works unchanged against either.
- **Interface segregation** — the reader interface (`list_channels`, `list_messages`, …) and the publisher interface (`post_channel_message`, `post_direct_message`) are separate on purpose, because a read credential must never be able to post (stated explicitly in the tool-doctrine sheet).
- **Dependency inversion** — everything above depends on the adapter *interface*, never on `GraphTeamsReader` directly; a factory reads config and injects the concrete implementation.

## 3. Technology stack (from the Tool Split sheet, applied)

| Concern | Choice | Why (per the plan's own reasoning) |
|---|---|---|
| Env / packaging | `uv` | One install command; fast, reproducible lockfile. |
| DB | SQLite + FTS5 | Zero setup, schema stays readable, committed as migrations not created ad hoc (SPN-04). |
| Scheduler | APScheduler + clock override | A "run digest" button is a test harness, not a scheduler (CHN-17). |
| LLM | Claude API (primary) via forced tool-use schema, Ollama 3B–8B (fallback) | Single swappable call site; caps token spend on a daily job (SPN-02). |
| Read path | Microsoft Graph, behind an interface | Only Graph gives message IDs, permalinks, edit history, delta tracking — all four feed the ledger and grounding (CHN-03/05). |
| Write path | Power Automate HTTP-triggered flow | Graph app permission to *send* is restricted; flow-bot posting is the pragmatic, and deliberately separate, write path (CHN-22). |
| Config surface | YAML (system of record) + Dataverse (human editing surface) | Dataverse is presentation, never the source of truth (CHN-02/25). |
| CLI/UI fallback | Streamlit or plain CLI | Must run with zero licensed software, no tenant, no credentials (scored path constraint). |

## 7. Cross-cutting safeguards (do not treat these as optional polish)

- **Scope gate at the boundary, not downstream** (CHN-04) — structurally impossible to read a non-allowlisted channel or any chat.
- **Three participation states, never collapsed** (CHN-10/14) — silent vs. chatted-without-updating vs. excused-by-leave must survive to the final rendered text.
- **Approval before any outbound message, ever** (SPN-08/09) — first publish, first nudge, first escalation per channel/person all gated; enforced at the service layer so no caller can route around it.
- **Grounding on every factual line** (SPN-06) — a summary line with no resolvable message ID is dropped and logged, not softened.
- **Idempotency** (CHN-17/18) — exactly one digest per channel per day, enforced by key, not by "don't click it twice."
